# Security policy

## Reporting a vulnerability

Report privately to the Docchain product owner through the private project channel. Establish an
external confidential route before sharing or deployment.

Do not describe an unfixed vulnerability in a public issue, a branch name, or a commit message. Those are
replicated widely and kept indefinitely.

## Handling

| | |
|---|---|
| Triage owner | Docchain product owner |
| Acknowledgement and remediation service levels | Not yet set; required before external sharing or deployment |
| Supported versions | None released yet |

- Exploit details stay out of public records until a fix is available.
- A committed secret is rotated first. Removing it from history does not make it safe again.
